# Sprint 10 — Beta Data Population Plan

**Status:** Sprint 10 readiness doc. **Plan only — no seed file expansion in this sprint.**
**Date:** 2026-05-17
**Scope:** Define what data closed beta needs, where it comes from, and the rules every entry must satisfy. Actual seed-file expansion happens in a follow-up run with verified sources.

## Sourcing rules (non-negotiable)

1. **No invented official data.** Every brand/model/generation/trim/spec/price must come from a verifiable public source (official manufacturer site, official dealer-published price list, verified import documentation). When the source is uncertain, the entry must be marked `status: "unverified"` and excluded from beta-public surfaces until verified.

2. **Every price has source + status.** Use the existing `CatalogPrice` shape:
   - `source` — short string identifying the source (e.g., `byd_official_az`, `dealer_premium_auto_pricelist_2026q1`, `community_submission`).
   - `status` — `verified` | `unverified` | `historical`. Only `verified` shows publicly in beta.

3. **Every dealer offer references `trim_id`.** No offer is allowed to reference a model or generation without a specific trim. Where the dealer lists a "Model X" without trim, the operator picks the closest matching trim and tags the offer `trim_match_confidence: "low"`.

4. **`generation_id` is required where it can be reasonably determined**, optional only when the model has a single active generation. The seed loader should fail loudly if a trim is added without `generation_id` for a multi-generation model.

5. **Missing data stays explicit.** Use `null` plus a sibling `*_unknown_reason` field where the schema supports it; never paper over a gap with a plausible-looking placeholder.

6. **Beta/staging marker.** Every seed entry created from non-public sources during beta must carry the marker `seed_origin: "beta_staging_2026"` (or equivalent — exact column name to be confirmed when extending the seed files). The marker is what lets a future cleanup pass scrub beta-only data before public launch.

## Per-entity sourcing strategy

### Trims (50–100)

Mix of:

- **BYD, Toyota, Hyundai, Kia, Honda, Volkswagen, Mercedes-Benz, BMW, Audi, Lexus** — top sellers in Azerbaijan. Official spec sheets from manufacturer sites; price ranges from local dealer published lists.
- **Chinese EV brands** (Li Auto, Nio, Hongqi, Zeekr, Geely) — official import data + dealer-published prices.
- **Pre-owned 2018–2023** generations where market activity is high.

Source provenance per trim must include:
- Official manufacturer URL (where applicable).
- Date the spec was checked.
- Operator initials.

Goal: 50 verified trims across ≥ 10 brands for beta launch; the rest can land iteratively during beta.

### Generations (10–20)

Tied to trim work — every trim references a generation. Generations are easier to verify because they're documented by year and chassis code.

### Dealers (5–10)

Recruit from the existing AZ dealer network (the 3 already seeded — Premium Auto, Nordic Motors, Caspian Auto Group — plus 2–7 new). See [DEALER_BETA_ONBOARDING.md](./DEALER_BETA_ONBOARDING.md) for the recruitment + onboarding flow. Dealer profiles must include:
- Legal name.
- Verified contact (phone + email).
- Physical location (verified via Google Maps).
- License/registration number (collected, not displayed publicly during beta).

### Dealer offers (20–50)

Generated by the dealers themselves during onboarding. The operator audits each offer before approval (see [ADMIN_OPERATOR_SOP.md](./ADMIN_OPERATOR_SOP.md) §offer-review). Every offer:
- References a real `trim_id`.
- Has a price within a reasonable band of the catalog price (or is flagged for review).
- Has at least one media asset.

### Content (news / encyclopedia / Q&A / Bazar Nəbzi)

Operator-authored or curated. For beta, prefer:
- News: 10–20 short-form market notes (new model launches, price changes, regulation updates) clearly dated.
- Encyclopedia: 10–20 educational entries (e.g., "What is range anxiety?", "BYD Blade Battery explained", "What VIN checks reveal"). All entries must not promise the Free Carfax-style VIN check that is internal-only in beta — per the Sprint 9 vocabulary policy.
- Q&A: 5–10 community questions with operator-vetted answers.
- Bazar Nəbzi (Market Pulse): 5–10 short market-trend posts.

### Media

- Key trims need at least one front 3/4 image.
- Dealers need at least one storefront/team photo.
- All media goes through [lib/media/validation.ts](../../lib/media/validation.ts): JPEG / PNG / WebP only; SVG rejected; magic-byte validation; ≤ 8 MB.

## Execution sequence (follow-up sprint, NOT Sprint 10)

1. Compile a sourcing spreadsheet (off-repo) — trims × source URL × verification date.
2. Extend [lib/cars/seed.ts](../../lib/cars/seed.ts) with new entries, batched per brand for reviewability.
3. Extend [lib/dealers/seed.ts](../../lib/dealers/seed.ts) with new dealer entries (or rely on the in-app dealer-onboarding flow — see §Dealers above).
4. Re-run `npm run db:seed` on staging.
5. QA each new entry against [BETA_DATA_QUALITY_CHECKLIST.md](./BETA_DATA_QUALITY_CHECKLIST.md).
6. Commit seed expansion in small PRs (one brand or one dealer per PR) so review stays tractable.

## Out of scope for Sprint 10

- Importing third-party datasets (no scraped data).
- Marketplace / private-seller listings.
- VIN-Check-derived data on public surfaces (VIN Check is internal-only).
- Pricing automation / web-scraped price feeds.
