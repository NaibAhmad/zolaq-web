# MVP_MONETIZATION_SUMMARY

## Goal

One-page executive summary of how Zolaq earns money at launch — what is live, what stays manual, what is deferred, and what Sprint 8 must ship before the first invoice goes out. For the full catalog of packages see `ADS_REVENUE_MODEL.md`; for placement rules see `AD_PLACEMENT_MAP.md`; for payment mechanics see `PAYMENT_INVOICE_FLOW.md`.

## What is manual / internal in MVP

Manual ≠ broken — manual is the explicit Sprint 7+8 strategy. Doing it manually is faster than building automation, and gives Sales / Content / Ops direct quality control until volume justifies investment.

- **Payments and invoices.** Bank transfer + manually-issued invoice/contract. Sales Manager flips `payment_status` through `pending → invoice_sent → paid` per `PAYMENT_INVOICE_FLOW.md`. No online payment, no card processing, no auto-renewal.
- **Data upload.** Catalog, dealers, offers, content, Bazar Nəbzi topics, ad placements all entered by Internal Ops Admin via the admin Form. Dealers submit data via WhatsApp / Email; Ops transcribes. See `DATA_UPLOAD_WORKFLOW.md`.
- **Dealer onboarding.** Sales Manager + Ops Admin run the full flow. No dealer self-service. No automated verification — Super Admin sets verification status manually.
- **Dealer offer approval.** Every new or updated offer is reviewed by Ops Admin before public.
- **Ad placement approval.** Two-key approval (Content Manager + Sales Manager) per `AD_PLACEMENT_MAP.md`. Homepage Sponsored Block adds a Super Admin third key.
- **Bazar Nəbzi topic management.** Content Manager schedules; Moderator reviews; sponsored topics require all three approvals (Content + Moderator + Sales) + `paid`.
- **Reporting.** Monthly Dealer Insight Report is generated by Sales Manager from internal queries + sent over email/WhatsApp. Automated dashboard is post-MVP.
- **Lead status updates.** Customer drives the state via the existing flow; Ops Admin updates on dealer's behalf when the dealer responds out-of-band.

## What is post-MVP

Explicitly deferred to Sprint 9+:

- **Dealer self-service dashboard.** Read-only at first (P1), then full self-service (P2). See `DEALER_PORTAL_SCOPE.md`.
- **Full CRM.** A real customer-relationship database for Sales/Ops with pipeline stages, tasks, follow-ups. MVP makes do with the admin Form + spreadsheets.
- **Online payments.** Card / direct bank integration with auto-receipt.
- **Subscription billing.** Auto-renewal, auto-invoicing, dunning.
- **Automated reports.** Dashboard for buyers showing real-time impressions / clicks / leads.
- **Bulk import / API import for dealers.**
- **Programmatic ad inventory** (auction, real-time bidding, etc.) — likely never relevant for this product.
- **In-product comments on Q&A** — see `COMMUNITY_MODERATION_SCOPE.md`.
- **Leaderboards / badges for Bazar Nəbzi participation** — P1 fun-only, non-redeemable.

## Hard policy reminders

These are not deferred — they are commitments:

- **No gambling, no betting, no real-money predictions, no crypto, no cash rewards** in Bazar Nəbzi. Ever. See `MARKET_PULSE_MODULE.md`.
- **Every paid placement carries a visible label.** No exceptions. See `AD_PLACEMENT_MAP.md`.
- **Sponsors cannot edit organic data, recommendation logic, vote counts, or final outcomes.** See `SPONSORED_MARKET_QUESTION_RULES.md`.
- **Lead / Sorğu data is private.** No public surface. No dealer "social proof" exposing other customers' leads. See `COMMUNITY_MODERATION_SCOPE.md`.

## What Sprint 8 must implement before real launch

Concrete list of P0 blockers for the first commercial day:

1. Admin authentication + role guard ([ROLE_PERMISSION_MATRIX.md](./ROLE_PERMISSION_MATRIX.md)).
2. Brand / model / trim / spec / image CRUD.
3. Dealer CRUD with verification-status transitions.
4. Offer / price CRUD with `valid_until` + source + verification + conflict flag.
5. Content CRUD (news / encyclopedia / Q&A) with draft / publish.
6. Bazar Nəbzi topic CRUD + close + resolve + sponsored approval gate.
7. Ad-placement CRUD with label enforcement.
8. Sponsored-placement two-key (or three-key) approval workflow.
9. Manual invoice / payment-status management with audit trail.
10. Lead-status update tooling (already exists internally — needs role guard).
11. Global audit log (append-only) for every admin write.
12. Moderation queue covering Q&A submissions, sponsored placements, and reports.
13. Homepage "Bazar nə deyir?" preview block component.
14. `/qa` Bazar Nəbzi tab with daily / weekly / monthly / tarixçə sub-views, reusing existing content components.
15. Tracking-event additions for Bazar Nəbzi (see [lib/tracking/events.ts](../../lib/tracking/events.ts) — Sprint 8 update).

Full list with priorities: `SPRINT_8_IMPLEMENTATION_REQUIREMENTS.md`.
